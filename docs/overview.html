Vendor onboarding: canonical workflow

Every state has a clear owner. Corrections are revisions of the same application; rejection is terminal.

Lifecycle

flowchart TD
 A[Vendor submits] --> B[Run all checks]
 B --> C{Evidence}
 C -->|clear| AP[Approved]
 C -->|correctable| VA[Pending: Vendor action required]
 C -->|uncertain or high risk| NR[Pending: Needs review]
 C -->|hard stop or 2 contradictions| RJ[Rejected]
 VA --> F[Prefilled correction, same application]
 F --> B
 NR --> T[Reviewer takes case]
 T --> D{Decide}
 D -->|approve| AP
 D -->|request info| VA
 D -->|reject| RJ

Payment-risk review

flowchart LR
 Q[Bank change or shared account] --> T[Reviewer claims case]
 T --> E[Review evidence and same/different comparison]
 E --> I[Trusted-contact callback or independent bank confirmation]
 I --> A[Approval unlocked and method audited]

Correction loop

sequenceDiagram
 participant V as Vendor
 participant S as System
 V->>S: Revision 1
 S-->>V: Vendor action required + numbered list
 V->>S: Correct prefilled application
 S->>S: Save revision 2 and rerun every check
 S-->>V: Current outcome
